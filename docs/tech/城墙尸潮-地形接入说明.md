## 3. 坐标与轴向

```
Blender（生成器内部，Z-up）        glTF / Godot（Y-up）
  ground  (gx, gy)          ->      x = gx ,  z = -gy
  height   z                ->      y
```

- 导出后实测包围盒 `X ∈ [-160,160]`、**`Y ∈ [-1.58, 42.32]`（Y = 高度轴）**、`Z ∈ [-160,160]`，轴向正确。
- 因为 `z = -gy`，地形在 Godot 里相对"直觉"是**前后镜像**。地基近似对称，观感无影响；但**按坐标摆放箱子/敌人时要按 `z = -gy` 换算**。
- 高度场：`heights[j*grid + i]`，`x = -160 + i*1.6`，`z = +160 - j*1.6`。

## 4. Godot 接入（已落地）

### 4.1 改动内容

`view/world_builder.gd` 只有两处改动：

1. 新增两个常量：
   ```gdscript
   const TERRAIN_SCENE := "res://art/assets/models/terrain/terrain_map_v001.glb"
   const USE_TERRAIN_MESH := true      # false = 回退老的程序化平面
   ```
2. `_add_ground()` 开头先尝试实例化地形，失败才走原来的平面逻辑：
   ```gdscript
   func _add_ground(cfg: ConfigDB) -> void:
       if USE_TERRAIN_MESH and _add_terrain_mesh():
           return
       ... 原有程序化平面代码（保留作兜底）...

   func _add_terrain_mesh() -> bool:
       var packed := load(TERRAIN_SCENE) as PackedScene
       if packed == null:
           push_warning("WorldBuilder: 地形 GLB 缺失，回退到程序化平面")
           return false
       var terrain: Node3D = packed.instantiate()
       terrain.name = "Terrain"
       add_child(terrain)
       return true
   ```

地形节点自带正确世界坐标（原点 = 水晶位置，y=0 = 逻辑地面），**不需要平移或缩放**。

### 4.2 为什么现在不加碰撞体

所有单位都在 `y=0` 平面内活动，可玩区 **r ≤ 84m 恒为 0**（实测），玩家活动半径 `roam_radius = 80m`——天然在平坦区内。
**第一版接入不加地形碰撞体**，避免 95k 面三角网拖累贴地采样。

> 2026-11-15 修：原来玩家被夹在 `scout_radius_max + 4 = 50m`，接上 320m 大地图后
> 会在空地中间撞上空气墙。现改为独立参数 `data/balance.json → world.roam_radius = 80`，
> 边界落在山脚；`scout_system` 的追兵边界同步改为 `roam_radius + 6`，
> 否则玩家能跑到 80m 而敌人停在 52m，搜集期变成无风险刷资源。

以后要做"爬山 / 高地"玩法，用 `terrain_map_v001.heights.json` 建 `HeightMapShape3D`：

```gdscript
const HEIGHTS := "res://art/assets/models/terrain/terrain_map_v001.heights.json"

func _add_terrain_collision() -> void:
	var data: Dictionary = JSON.parse_string(FileAccess.get_file_as_string(HEIGHTS))
	var g: int = int(data.grid)            # 201
	var cell: float = float(data.cell_m)   # 1.6
	var heights: Array = data.heights      # 行沿 gy 增大 = Godot z 减小

	# HeightMapShape3D 是 map_data[z * width + x]，z 随行号增大；整行翻转一次
	var arr := PackedFloat32Array()
	arr.resize(g * g)
	for zi in g:
		var src: int = (g - 1 - zi) * g
		for xi in g:
			arr[zi * g + xi] = float(heights[src + xi])

	var shape := HeightMapShape3D.new()
	shape.map_width = g
	shape.map_depth = g
	shape.map_data = arr

	var cs := CollisionShape3D.new()
	cs.shape = shape
	cs.scale = Vector3(cell, 1.0, cell)    # 顶点间距恒为 1 单位，必须缩放

	var body := StaticBody3D.new()
	body.name = "TerrainCollision"
	body.add_child(cs)
	add_child(body)
```

### 4.3 贴图（可选）

GLB 自带平色材质即可用。若要贴现有地面贴图：GLB 已生成 **XZ 平面投影 UV，每 9m 一张**（对齐 `GROUND_TILE_METERS`），直接挂 `albedo_texture` 即可；陡坡建议开 `uv1_triplanar`。

### 4.4 防跑出地图

给 `PlayerSystem._clamp_pos` 加一条 `radius <= 56`（与现有城墙内 clamp 同处）。不要用碰撞墙——会与 `Combat` 的解析几何命中判定脱节。

## 7. 已知限制

1. **无贴图**，只有平色。地面细节（石板纹、草地）要靠引擎贴图或后续烘焙。
2. **无 AO / 法线烘焙**。低模平色本身不依赖，但需要 SSAO 补体积感。
3. **道具是静态合并网格**，不可交互（枯树不可砍、石头不可采）。要做资源点需拆成独立实例。
4. **河流是背景地貌**：最近距城心 88m，游戏相机（正交 26m、跟随玩家且玩家活动半径 ≤46m）里基本看不到，只在俯瞰/远景可见。若希望玩家能看见河，需要改玩法半径或把河移近——但**移近会破坏可玩区 y=0**。
5. **地图在 ±160m 直接截断**，边缘靠山体抬升 + 雾遮挡。
6. **色块边界沿 1.6m 三角面走**，放大看仍有阶梯感——纯色块低模方案的固有特征。
7. **单位必须留在 r ≤ 56m 内**。超出会踩到起伏地面，而 `core` 假定 y=0。
8. **水面是静态网格**，没有流动动画、没有反射/折射。要流动感得在 Godot 里用 shader 滚动 UV。
