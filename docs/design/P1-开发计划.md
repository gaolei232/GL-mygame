## 三、验收标准

### P1-1 守卫 AI

1. 进入 `build` 时按 `crystal_level` 补齐守卫到 `guard_count`，满血、复位到固定站位，免费。
2. `wave` 期间守卫死亡不复活；HUD 顶部显示「守卫 N/G」（补充时一次性提示，不用红色）。
3. 状态机四态：`idle / intercept / attack / return`，目标优先级按 §5.3：先「越破口且距水晶 ≤12m」，再「距水晶最近」，最后「本回合无目标则回站位」。
4. 数值完全来自 `data/numeric/guards.tsv`（HP 480 / 护甲 4 / 攻击 16 / 间隔 1.0s / 追击 18m / 复位 5m）。
5. 守卫能独立击杀第 2 波进入城内的 walker（单人存活 ≥8s，对齐 §5.3 的承载力推导）。
6. headless 断言：守卫数量随水晶等级变化；波间补满；波内不复活。

### P1-2 精良箱驻守

1. `refined` 箱生成时附带 2–4 只驻守敌人，位置在箱周 3–6m。
2. 箱子在驻守敌人全部死亡前不可开启（靠近不结算、不消耗）。
3. 普通箱不设防（行为不变）。
4. headless 断言：驻守未清时 `opened == false`；清空后一次靠近即开。

### P1-3 可读性

1. 遮挡淡出：相机与玩家连线穿过的墙段降到 25% 透明度，离开即恢复；不改碰撞与逻辑。
2. 精确瞄准：右键按住时正交尺寸 ×0.85、移速 ×0.6、散布收紧 50%。
3. 屏外指示：屏幕外 2 秒内会进城的敌人在屏幕边缘显示方向箭头。

### P1-4 词条/配件/背包/稀有度（待设计确认）

1. 稀有度只影响掉落分布与基础属性倍率，不改变已定数值曲线。
2. 词条池每类 3–5 条，单件最多 2 条，效果必须是「修饰现有字段」而非新增判定。
3. 背包只承载词条物品，不承载资源；容量与解锁沿用 §6.5。
4. 概率类内容必须公示概率（合规红线）。

### P1-5 数值校准

1. 3 个固定种子 × 5 局，输出通关率、单局时长、破口次数、死亡次数、剩余砖/金。
2. 通关率 60%–90%、单局 15–20 分钟、第 3 波前死亡 ≤2 次为达标区间。
3. 不达标只调 `balance.json` / TSV，不改规则代码。

### 修掉的缺陷

- `GameState.setup()` 未清空 `items/equipped/mods`：重开局后上一局词条继续生效 → 新局清零。
- `InventorySystem.sell()` 只返回售价不加钱：改为**卖出即结算**（调用方不再自行加 coin）。

### 遗留

1. 词条不影响守卫/城墙/敌人（刻意，保 Φ(w) 预算）。
2. 背包不可扩容、无合成/洗词条、无保底池——P2。
3. 稀有度权重可公示，但游戏内还没有"概率说明"面板（合规项，P2 补 UI）。
