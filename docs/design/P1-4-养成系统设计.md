# P1-4 养成系统设计（稀有度 / 词条 / 配件 / 背包）

> 版本：v1（2026-11-05）｜状态：**实现依据**（写完即开工，不再等确认）
> 设计红线：只用「修饰现有字段」的方式做养成，**不新增判定分支**；概率类必须可公示。

## 一、为什么这么做

现在的局内成长只有两条：武器升级（数值台阶）和奖励三选一（一次性）。缺的是**局内可交易的长期选择**——玩家在 `build` 期除了买建材没有别的花钱理由，商店第 6 格因此空着。

养成系统解决三件事：
1. 给 `coin/metal` 第二个出口（词条物品）；
2. 让"这局走什么流派"从第 1 波的主题四选一，延伸到每一波的具体装备；
3. 用稀有度把"运气"限制在可接受区间（波次越高，最低档越高）。

## 二、稀有度（4 档）

| 档 | 名称 | 数值倍率 | 卖出价 | 波次权重（1–2 波 / 3–4 波 / 5 波） |
|---:|---|---:|---:|---|
| 0 | 普通 | ×1.00 | 40 | 70% / 35% / 0% |
| 1 | 精良 | ×1.25 | 80 | 30% / 45% / 30% |
| 2 | 稀有 | ×1.60 | 140 | 0% / 20% / 50% |
| 3 | 传说 | ×2.10 | 240 | 0% / 0% / 20% |

- 倍率作用在**词条数值**上（例：锋芒 +8% → 传说 +16.8%），不改武器基础数值。
- 权重表进 `data/items.json`，改表即改分布，不动代码。

## 三、词条 / 配件（同一套管线，两个装备位）

| 字段 | 说明 |
|---|---|
| `kind` | `trait`（词条）或 `attachment`（配件） |
| `stat` | 只允许：`dmg` / `rate` / `spread` / `repair` / `speed` |
| `base` | 基础数值（`rate`、`spread` 为负值 = 更快/更准） |

词条池（v1 共 7 条，词条 5 + 配件 2）：

| id | 名称 | kind | stat | base | 一句话 |
|---|---|---|---|---|---|
| `sharp` | 锋芒 | trait | dmg | +8% | 伤害 |
| `quick` | 速射 | trait | rate | −6% | 射击间隔 |
| `steady` | 稳固 | trait | spread | −10% | 散布 |
| `mason` | 巧匠 | trait | repair | +15% | 修墙量 |
| `scout` | 轻装 | trait | speed | +6% | 移速 |
| `barrel` | 配重枪管 | attachment | dmg | +12% | 伤害 |
| `trigger` | 轻机 | attachment | rate | −8% | 射击间隔 |

**上限**：词条 2 个 + 配件 1 个。装不下就提示"装备位已满"，不做自动替换——自动换装会让玩家在紧张的 build 期丢东西。

**叠加方式**：同类相加，跨类相乘。例：锋芒(+8%) + 配重枪管(+12%) → 伤害 ×1.20；两个速射(−6%, −8%) → 间隔 ×0.86。

## 四、背包

- 容量 **10 格**（沿用 §6.5 的 `backpack_level=1=10`），本版不做扩容购买。
- 只能存词条/配件，不存资源（资源是无限堆叠的账本，不是物品）。
- `build` 期按 `Tab` 打开背包：装备 / 卸下 / 卖出。
- 背包满时商店拒绝售出词条（不吞钱）。

## 五、掉落与获取

| 来源 | 规则 |
|---|---|
| 商店第 6 格 `普通词条` | 180 coin + 3 metal，限购 1；按当前波次权重抽 1 件 |
| 精良箱 | 打开时额外掉 1 件（提升精良箱价值，呼应 P1-2 的驻守成本） |
| 波末奖励 | 不改（奖励仍是资源/武器，不塞物品，避免奖励池稀释） |

| 层 | 文件 | 改动 |

## 七、验收标准

1. `items.json` 加载失败或 stat 越界 → 启动报错，不进入游戏。
2. 波 1–2 抽不到稀有以上；波 5 只出精良以上（按权重）。
3. 装备 2 词条 + 1 配件后，`mods()` 数值与手算一致（误差 < 0.001）。
4. 装备词条后，同一把弩对同一敌人的单发伤害按倍率提升。
5. 背包满 → 商店购买被拒且**不扣钱**；卖出 → 背包 −1、金币 + 卖出价。
6. 卸下后 `mods()` 立即回落。
7. 概率相关（稀有度权重）写在 JSON 里，可被玩家/QA 直接查阅（合规）。

## 八、明确不做（本版）

- 背包扩容、物品合成、洗词条、限定池与保底 —— 都需要单独的数值模型，不在 P1-4。
- 词条不影响敌人、守卫、城墙数值（避免"养成改难度预算"导致 §8.2 的 Φ(w) 失效）。
